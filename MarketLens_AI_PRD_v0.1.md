# 1. 问题陈述

## 1.1 用户痛点

产品研究过程中，大量真实用户反馈分散在：

-   淘宝；
-   GitHub Issues；
-   产品评论；
-   社区讨论。

这些文本包含重要的：

-   用户痛点；
-   功能需求；
-   使用场景；
-   产品满意点。

但是人工分析存在以下问题：

## 信息规模过大

当反馈数量达到数千条甚至更多时，人工逐条阅读成本过高。

## 难以识别高价值反馈

大量评论属于：

-   简单情绪表达；
-   重复观点；
-   无具体信息反馈。

真正具有产品价值的信息通常包含：

-   明确问题；
-   使用背景；
-   影响描述；
-   改进建议。

人工难以快速筛选。

## 分析容易受到主观影响

研究者容易：

-   被少量高热度评论影响；
-   只关注符合已有认知的信息；
-   忽略低频但关键的问题。

# 2. 为什么必须使用 AI

传统方法：

## 人工分析

优势：

-   能理解复杂语义。

问题：

-   无法处理大规模文本。

## 关键词搜索

优势：

-   快速。

问题：

无法理解：

-   同义表达；
-   隐含需求；
-   用户真实意图。

例如：

以下文本可能表达同一个问题：

> The subscription is too expensive.

> The price does not match the value.

> I cannot justify paying monthly.

传统关键词难以聚合。

------------------------------------------------------------------------

## AI 的核心价值

MarketLens AI 使用：

-   GLiNER2 轻量语义模型；
-   LLM Agent 推理能力；
-   LangGraph 工作流编排；

实现：

> 低成本筛选海量反馈，将高价值信息交给大模型进行深度分析。

系统遵循：

Small Model Perception → Large Model Reasoning

架构。

# 7. Multi-Agent Workflow 设计

## Agent 1：Research Planner Agent

职责：

根据用户目标制定研究计划。

输入：

-   产品名称；
-   分析目标。

输出：

``` json
{
"sources":["taobao"],
"keywords":["pricing","performance"],
"dimensions":["strength","weakness"]
}
```

------------------------------------------------------------------------

## Lightweight Semantic Routing Layer

### GLiNER2

职责：

在进入 LLM Agent 前进行低成本语义分析。

输入：

原始评论。

输出：

``` json
{
"text":"",
"sentiment":"negative",
"topic":["pricing"],
"feedback_value":"actionable",
"confidence":0.86
}
```

------------------------------------------------------------------------

### 路由逻辑

高价值反馈：

    feedback_value == actionable

进入：

Review Analyst Agent。

低价值反馈：

仅用于统计。

------------------------------------------------------------------------

## Agent 2：Review Analyst Agent

职责：

分析经过 GLiNER2 筛选后的高价值反馈。

输出：

-   高频问题；
-   用户满意点；
-   主要痛点；
-   用户需求趋势。

------------------------------------------------------------------------

## Agent 3：Visualization Agent

职责：

将分析结果转换为可视化结构。

输出：

``` json
{
"chart":"bar",
"title":"Top User Complaints"
}
```

前端根据 schema 渲染。

# 8. 功能需求

## FR-001 用户输入

用户输入：

-   产品名称；
-   分析目标；
-   淘宝商品链接（选择淘宝来源时必填）。

------------------------------------------------------------------------

## FR-002 Research Planner Agent

生成：

-   数据来源；
-   搜索关键词；
-   分析维度。

------------------------------------------------------------------------

## FR-003 数据采集

淘宝来源按指定商品链接，通过浏览器读取可见评价并分页或加载更多；登录由用户在本地完成。采集数量受页面可见范围影响，返回实际采集数量及是否完整。登录失效、页面验证或结构变化时返回已采集数据和提示；本地CSV/JSONL作为离线输入。

v0.2 支持：

-   淘宝商品评论（按用户指定的商品链接采集）；
-   本地评论数据集。

统一格式：

``` json
{
"text":"",
"source":"taobao",
"product_id":"",
"url":"",
"time":""
}
```

------------------------------------------------------------------------

## FR-004 GLiNER2 Semantic Routing

功能：

对评论进行：

-   情感分类；
-   主题抽取；
-   可行动价值判断。

输出结构化结果。

------------------------------------------------------------------------

## FR-005 Review Analyst Agent

分析：

高价值反馈集合。

生成：

-   问题聚类；
-   原因总结；
-   用户需求分析。

------------------------------------------------------------------------

## FR-006 Visualization Agent

生成：

-   图表配置；
-   Dashboard 数据结构。

------------------------------------------------------------------------
